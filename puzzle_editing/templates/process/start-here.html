Start here

PuzzUp is where our team tracks every puzzle from first idea to the finished page on the hunt website. This page covers everything you need for day-to-day use. For the full reference, see How to use PuzzUp.

The site can take up to a minute to load if nobody has used it for a while. It runs on free hosting that goes to sleep. After the first page, it's quick.

Where things live

1. Join

  1. Create an account. You'll need the site password, which you can get from c12.
  2. On your account page, set your display name and time zone, and link your Discord account. PuzzUp only adds you to a puzzle's Discord channel if your accounts are linked.
  3. Want to be an editor? Ask c12. Editors can create rounds and answers and assign answers to puzzles.

2. The life of a puzzle

Every puzzle has a status. It tells everyone where the puzzle is and who it's waiting on. A typical puzzle goes:

🥚 Initial Idea → 🎩 Awaiting Approval By EIC → ✏️ Writing → 💡 Ready to be Testsolved → Revising → Needs Solution → Ready for Postprodding → Needs Factcheck → Needs Copy Edits → Done
  • Anyone on a puzzle can change its status. PuzzUp suggests the usual next step on the puzzle's page, but nothing is enforced, so change it whenever it reflects reality.
  • Each status is "blocked on" someone: the authors, the editors, the testsolve coordinators, and so on. ✋ My Puzzles shows what's waiting on you.
  • Changing the status notifies people. Authors and editors get an email and a message in the puzzle's Discord channel.
  • Puzzles that won't be used go to Deferred (maybe later) or Dead (not happening). They're hidden from most lists.

3. Submit an idea

  1. Click ➕ Add. A rough idea is fine. You can note what kind of answer you'd like (length, theme, letter constraints).
  2. PuzzUp creates a brainstorm sheet in the Puzzle Drafts Drive folder and a Discord channel for the puzzle. The sheet's link appears in the puzzle's Solution box. Keep it there when you add the solution doc link later.
  3. When you want an editor, set the status to Awaiting Approval By EIC. c12 will pick one.
  4. When the idea is approved, your editor assigns an answer and the status moves to Writing.

Spoilers: opening a puzzle's page marks you as spoiled on it, which means you can't testsolve it. Use the lists to see titles without opening puzzles you might want to testsolve. My spoiled puzzles (under More) shows which ones you've seen.

4. Write it

  • Write the puzzle and its solution in two Google Docs inside the Puzzle Drafts folder. PuzzUp can only read docs in our team folders, or docs shared with aleaffallingintothedarkness@gmail.com.
  • Put the links on the puzzle page: the puzzle doc under Puzzle, the solution doc under Solution. Postprod picks them up automatically later.
  • Keep discussion in the puzzle's Discord channel or as comments on the puzzle page. Comments are kept with the puzzle and emailed to its authors and editors.

5. Testsolve

Getting your puzzle testsolved: set its status to Ready to be Testsolved. Then on ✏️ Testsolve, start a session, put the date and time in its notes, and share the link in our Discord. Aim for 2 clean testsolves before moving on.

Testsolving someone else's puzzle:

  1. On ✏️ Testsolve, start a new session next to a puzzle you can testsolve, or join an open session.
  2. PuzzUp creates a testsolve sheet in the Testsolving folder. Solve in it, and use the session page to check answers and leave comments.
  3. When you finish (or give up), click Done with the puzzle? and fill in the feedback form: fun, difficulty, time spent, and what worked or didn't. Authors rely on this, so be specific.

6. Postprod: from Google Doc to hunt website

Once the puzzle and solution are final, PuzzUp converts the Google Docs into pages for the hunt website.

  1. On the puzzle's page, find the Postprod section and click start one now.
  2. The puzzle and solution doc links are usually filled in already. Choose a slug: the puzzle's address on the hunt site. For example, fifty-fifty becomes /puzzles/fifty-fifty. Use lowercase words and dashes, and don't put spoilers in it.
  3. Submit. It can take a minute. PuzzUp converts the docs (text, tables and images), then pushes them to a new branch named after the slug in the hunt site's GitHub repo.
  4. c12 reviews that branch, polishes anything interactive or unusual, and merges it.

You can run postprod again after editing the docs. It updates the same branch.

For the web team: checking a postprod branch
  1. git fetch, then git checkout <slug> in the hunt site repo.
  2. Run ./scripts/load_fixtures to load the puzzle's metadata.
  3. Open the puzzle and solution pages locally and fix anything the conversion missed. Complex formatting, special fonts and interactive parts usually need hand work.
  4. Commit and merge into main.

7. Factcheck, copy edit, done

  • Moving a puzzle to Needs Factcheck creates a factcheck sheet from our template in the Factchecking folder. Factcheckers work through it and comment on the puzzle.
  • Needs Copy Edits covers wording, spelling and consistency with house style.
  • When everything is signed off, set the status to Done 🎉.
